# Domain docs

This repo uses a single-context layout: `GLOSSARY.md` at the root and repo-wide ADRs in `docs/adr/`.

## Before exploring a code area

- Read `GLOSSARY.md` when it exists.
- Read ADRs in `docs/adr/` that affect the area.

These files are created as terms and decisions are resolved. If one does not exist yet, continue without it.

## Use the glossary's vocabulary

Use glossary terms in issues, proposals, hypotheses, and tests. When a needed concept is absent, reconsider the term or note the gap for `/domain-modeling`.

## Flag ADR conflicts

If proposed work conflicts with an ADR, identify the ADR and explain the conflict.
