# ML-19 configured property saves

Spec: [ML-19](https://github.com/Dzahc/MacroLoom/issues/19), PRD sections 4.5,
4.8, 7, 9 and 11. The implementation connects the existing owned Configure
window to backend validation and atomic repository updates.

## Agreed decisions

- External file changes or deletion reject Save, including unchanged Save.
  Keep the open draft and explain that restarting reloads external changes but
  loses that draft. Drafts need not survive application restart.
- After deliberate Save begins, block Cancel, Escape and native dismissal until
  the worker finishes. A precommit failure retains the draft and clears deferred
  application exit.
- Equal normalized saved properties close Configure without writing, changing
  `updatedAt`, advancing the library revision or showing an Updated toast. This
  is the agreed exception to the issue/PRD's successful-save toast requirement.
  Valid inactive repeat settings participate in equality and remain editable
  settings for subsequent mode switches.
- The disk commit is authoritative. Construct validated metadata before commit;
  install it after commit without a second file read. Cache trouble returns a
  saved receipt with a persistent refresh warning, never an ordinary failure
  claiming the previous file survived.
- Retain the native completion until the next editor opening. A lost command
  acknowledgement queries that completion without writing again. When status
  is also unavailable, retain and freeze the submitted draft until Retry checks
  the outcome; do not silently discard newer edits after recovering an older
  committed result.

## Automated coverage

- Repository tests exercise complete property persistence after a fresh load,
  metadata-only rename with stable ID/filename, preserved recording/events and
  unknown metadata, invalid backend values, unchanged saves, inactive settings,
  and changed/missing external files.
- A Windows filesystem test holds the original file open without delete sharing.
  Atomic replacement fails while original bytes and cached values survive, the
  staging file is removed, and Retry succeeds after releasing the handle.
- Configure boundary tests reject unknown repeat modes and fractional/negative
  numbers with rendered field diagnostics. Existing tests cover frozen identity,
  ranges, operation exclusion, pending cancellation and deferred exit.
- Frontend recovery tests cover acknowledgement loss while work is pending,
  recovered precommit failures, unknown-result draft retention, timer cancellation,
  selection-preserving library reconciliation, deduplicated named timed outcomes,
  and persistent saved/refresh warnings after toast dismissal.
- Existing form tests cover accessible field labels, active/inactive settings,
  Cancel, validation, retained draft strings, and successful Retry behavior.

## Validation result

Initial focused frontend Configure tests: 17 passed. Repository tests: 21 passed,
including the Windows atomic-replacement failure and Retry test. Rust Clippy
with `--locked --offline --all-targets -- -D warnings` passed.

Review caught an uncertain-result Retry that could unlock edits before the worker
finished. Retry now queries the outstanding native result before any submission;
uncertain Cancel/Escape remain blocked. Close errors also leave the form visible.
The unused frontend acknowledgement channel was removed, so native completion
state alone owns the outcome.

Follow-up cleanup removes the unused frontend delivery bridge, its four obsolete
callback tests and the frontend `ConfigureSubmission` type. The editor capability
test now lives with persistence coverage, preserving the check that frontend
event emission remains unavailable.

Final completion gate: `npm.cmd --prefix app run verify` passed (exit 0).
All formatting, type checking, lint, production build, Clippy and maintained test
suites passed after cleanup: 64 frontend/tooling tests, 43 Rust tests (one interactive native
window test remains intentionally ignored), and 33 quality fixture tests.
Complexity checked 745 functions across the index/worktree with no scores above 10. Both initial implementation reviews (Standards and Spec) have no remaining findings after fixes.

Native owned-window interaction and assistive-technology announcements have not
been manually exercised in this change. Filesystem tests are Windows integration
evidence; controller/form tests are deterministic evidence. Native input remains
confined to the existing debug prototype mode; this story preserves that boundary.
